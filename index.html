    ZATCA e-invoicing for your application¶

    fatoority is an open-source toolkit for developers building e-invoicing integrations in Saudi Arabia. Sign invoice XML, validate it locally, generate QR payloads, and connect to ZATCA APIs for Phase 1 and Phase 2 workflows.

    Use the Rust library, add it to your application in Python, JavaScript/TypeScript, C#, Kotlin/Java (including Android), or C/C++, or run the command-line tool from your terminal.

    Try it Choose your language View on GitHub

    fatoority is an independent project and is not affiliated with ZATCA.

    What you can build¶

    Task How fatoority helps
    Create and sign invoices Build invoice data and sign XML for standard and simplified invoices, credit notes, and debit notes.
    Validate invoice XML Check UBL schemas, local ZATCA business rules, and applicable signature and QR checks before submission.
    Generate QR payloads Generate base64-encoded invoice QR data or read the payload embedded in signed XML.
    Generate a certificate signing request Create a signing key and CSR for device onboarding.
    Hash invoices Compute invoice hashes and prepare invoice request payloads for API submission.
    Connect to ZATCA Integrate onboarding, compliance checks, reporting, and clearance into your application.

    Local validation helps catch problems before submission. It does not establish ZATCA gateway acceptance or certificate issuer trust. See the validation guide for coverage and how to interpret results.

    Try it: validate an invoice¶

    Start with a local XML schema check. You do not need an account, certificate, or API credentials for this example.

    1. Install the CLI¶

    With Rust and Cargo installed, run:

    cargo install fatoora-cli

    You can also download a binary for your platform from GitHub Releases. Extract the archive and put the fatoora executable on your PATH.

    2. Download the sample invoice¶

    Save sample-invoice.xml in your working folder. It contains demonstration data for this schema check.

    3. Run the check¶

    From the folder containing the file:

    fatoora validate --invoice sample-invoice.xml

    Expected output:

    OK

    OK means the XML passes the bundled UBL schema check. To run local ZATCA rules and inspect individual findings, follow the invoice validation guide. For more terminal commands, see the CLI guide.

    Choose your language¶

    Install the package for your application, then follow its examples. The project and most packages are named fatoority; existing API names such as Python's fatoora import and Rust's fatoora_core remain unchanged.

    cargo add fatoora-core

    Import fatoora_core in your code. Start with invoice signing or browse the Rust API reference.

    pip install fatoority

    Import fatoora in your code. Follow the Python setup and examples.

    npm install fatoority

    Use the WebAssembly package in Node.js or a browser. Follow the JavaScript/TypeScript setup and examples, including browser asset setup and API transport requirements.

    dotnet add package Fatoority

    Use the Fatoora namespace with .NET 8 or later. Follow the C# setup and examples, including supported native platforms.

    Install from Maven Central with Gradle or Maven.

    Gradle (build.gradle.kts):

    repositories { mavenCentral() }
dependencies {
    implementation("com.fatoority:fatoority:0.4.4")
}

    Maven (add inside <dependencies> in pom.xml):

    <dependency>
  <groupId>com.fatoority</groupId>
  <artifactId>fatoority</artifactId>
  <version>0.4.4</version>
</dependency>

    Import com.fatoora in your code. Follow the Kotlin/Java examples for supported platforms and Android setup. For Android, use com.fatoority:fatoority-android:0.4.4 instead of the desktop artifact.

    Download the fatoora-ffi-* archive with the native library and C/C++ headers from GitHub Releases.

    Follow the C/C++ setup and examples for compilation and linking instructions.

    Continue your integration¶

    If you are adding invoicing to an application, start with building and signing an invoice, then validate the XML before sending it.

    For device onboarding, generate a CSR, then use the ZATCA API client to request credentials and submit invoices. The guides explain the inputs needed at each step.

    About the project¶

    The core is written in Rust and shared by the CLI and language bindings. The project code is available under the MIT or Apache-2.0 license. Third-party materials retain their upstream terms; see the third-party notices.

    See the SDK compatibility notes for the scope of comparison with the official SDK, and benchmarks for measured performance and methodology.

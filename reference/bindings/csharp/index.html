    C# package reference¶

    Use the Fatoority NuGet package to build, sign, and validate invoices and send ZATCA API requests from .NET 8 or later. Public classes use the Fatoora namespace. The package includes the native library for its supported platforms.

    Install from NuGet¶

    In your application project, install the published package:

    dotnet add package Fatoority

    Use the Fatoora namespace. Check the supported native platforms below before deploying your application.

    Supported platforms¶

    Runtime identifier Platform
    linux-x64 Linux x86-64, glibc 2.28 or later
    win-x64 Windows x86-64
    osx-arm64 macOS Apple Silicon

    Match your application's OS and architecture to a packaged runtime identifier. NuGet supplies the native asset at runtime; no library search-path override is needed. Linux musl/Alpine is not included. A package built locally inherits its build host's libc requirements.

    Example¶

    Import Fatoora and dispose native objects when finished:

    using Fatoora;

using var config = Config.New(0);
using var key = SigningKey.Generate();
using var bytes = key.ToDer();
using var view = bytes.AsSlice();
byte[] privateKey = view.Clone();

    privateKey is an independent managed copy. Keep it secure; disposing the native objects does not erase that array. Follow the CSR guide for a complete credential-generation workflow.

    Use environment 0 for nonproduction, 1 for simulation, and 2 for production. Configuration, CSR generation, and credentials must agree on the environment. See the CSR, signing, validation, and QR guides for complete C# examples.

    Values and ownership¶

    Value C# representation
    Text input string; invalid UTF-16 and embedded NUL are rejected
    Optional text input string?; null and "" remain distinct
    Optional text output Text?; read Value() and dispose the owner when present
    Decimal amount Invariant decimal string; use CultureInfo.InvariantCulture for conversion
    Invoice counter ulong
    Owned native object An IDisposable class; use using or call Dispose()
    Owned binary output Bytes; call AsSlice() and copy with Clone() when needed
    Invoice acceptance InvoiceOutcome.Accepted, Rejected, or Unknown

    Native object classes implement IDisposable, including returned snapshots and BindingError. Disposal is idempotent; later calls on that wrapper throw ObjectDisposedException. Finalization provides cleanup if disposal is omitted, but its timing is not deterministic. Releasing an owner does not guarantee zeroization of secrets or copies exported to managed strings and arrays.

    InvoiceBuilder.Build(), Signer.Sign(), and SignedInvoice.IntoXml() consume inner state. The outer wrapper remains disposable, but reusing consumed state raises BindingErrorException. Build and signing failures can also consume state. Returned invoice data, totals, addresses, and response children are owned snapshots and remain usable after their parents are disposed.

    For binary output, dispose both the owner and its borrowed view:

    using Fatoora;

using var key = SigningKey.Generate();
using var bytes = key.ToDer();
using var view = bytes.AsSlice();
byte[] der = view.Clone(); // Independent managed copy.

    WithSpan() provides a scoped, read-only view without copying. An active read retains native memory through concurrent source disposal. Later reads fail after the source is disposed. Disposing the view while a read is active throws InvalidOperationException; retry once the read has finished. Conflicting calls that require mutable access also throw InvalidOperationException.

    Errors¶

        public static void ShowError()
    {
        try
        {
            using var key = SigningKey.FromPem("invalid key");
        }
        catch (BindingErrorException error)
        {
            using var details = error.Inner;
            Console.WriteLine($"{details.Code()}: {error.Message}");
            Console.WriteLine(details.DetailsJson());
        }
    }

    BindingErrorException.Message contains the native message. Inner.Code() uses the shared error codes, and Inner.DetailsJson() preserves structured details such as HTTP status and response body. Dispose Inner after reading it. Invalid UTF-16 fails before the native call with EncoderFallbackException; invalid native inputs, including embedded NUL, use BindingErrorException.

    API requests¶

    Create a client with ZatcaClient.Create(config). Dispose the client, credentials, and responses with using. The following methods return owned objects:

    Method Inputs Returns
    PostCsrForCcsid(csr, otp) Csr, OTP string CsidCompliance
    PostCcsidForPcsid(credentials) CsidCompliance CsidProduction
    RenewCsid(credentials, csr, otp, acceptLanguage) CsidProduction, Csr, OTP, nullable language string CsidProduction
    CheckInvoiceCompliance(invoice, credentials) SignedInvoice, CsidCompliance ValidationResponse
    ReportSimplifiedInvoice(invoice, credentials, clearanceStatus, acceptLanguage) SignedInvoice, CsidProduction, Boolean, nullable language string ValidationResponse
    ClearStandardInvoice(invoice, credentials, clearanceStatus, acceptLanguage) SignedInvoice, CsidProduction, Boolean, nullable language string ValidationResponse

    All listed arguments are required, including nullable arguments: pass null when no language override is needed. clearanceStatus sets the clearance-status request header; use false for ordinary reporting and true for clearance. It does not describe the result of the operation.

    The native client methods block the calling thread. HTTP success alone does not establish invoice acceptance: inspect Outcome() or call EnsureAccepted(). For clearance, ClearedInvoiceXml() returns Text?: when present, read Value(), save the text, and dispose the returned owner. See the API guide for rejection, unknown outcomes, and cleared-document semantics.

    Prepared requests¶

    Blocking method Prepared equivalent Credential scope / result
    PostCsrForCcsid PreparePostCsrForCcsid CSR and OTP to compliance credentials
    PostCcsidForPcsid PreparePostCcsidForPcsid Compliance to production credentials
    RenewCsid PrepareRenewCsid Production credentials, CSR and OTP to renewed credentials
    CheckInvoiceCompliance PrepareCheckInvoiceCompliance Compliance credentials; validation response
    ReportSimplifiedInvoice PrepareReportSimplifiedInvoice Production credentials; reporting response
    ClearStandardInvoice PrepareClearStandardInvoice Production credentials; clearance response

    PreparePostCsrForCcsid returns ComplianceRequest; credential exchange and renewal return ProductionRequest; invoice operations return InvoiceRequest. Their arguments match the corresponding blocking method.

    For asynchronous HTTP or cancellation, use a Prepare* method and your own HttpClient. The request exposes Method(), Url(), HeadersJson() (a JSON array of header pairs), and an owned Body(). Copy its bytes before awaiting the transport. Pass the HTTP status and response bytes to Decode(ushort, byte[]), including non-2xx responses, so the library can classify gateway errors. Decode returns an owned CsidCompliance, CsidProduction, or ValidationResponse matching the request type; dispose it after use. Configure the transport to refuse redirects, and pass your cancellation token to send/read operations. The generated blocking methods do not accept a cancellation token.

    Prepared requests own their wire data, credentials, and decoding context; keep the request alive until decoding completes. Headers contain credentials and should not be logged.

    Local validation¶

    Method Inputs Returns
    Xml.Validate(config, xml) Live Config, invoice XML string true on schema success; throws on malformed XML or schema rejection
    Xml.ValidateZatca(config, xml, optionsJson) Live Config, invoice XML string, nullable options JSON string JSON report string, including rejection or incomplete coverage
    Xml.Hash(xml) Invoice XML string Base64 invoice hash; throws when XML cannot be processed

    Pass null explicitly for default validation options. Otherwise, serialize an object containing previous_invoice_hash and/or evaluated_at; unknown option fields are rejected. The evaluation timestamp uses RFC3339 format.

    using Fatoora;
using System.Text.Json;
using System.IO;

string invoiceXml = File.ReadAllText("invoice.xml");
using var config = Config.New(0);
using var report = JsonDocument.Parse(Xml.ValidateZatca(config, invoiceXml, null));
bool valid = report.RootElement.GetProperty("is_valid").GetBoolean();

    Xml.ValidateZatca(config, xml, optionsJson) returns a JSON report string. Inspect is_valid and stages; a rejected document returns a report, while an execution failure throws an exception that may carry a partial report in its details. Provide the predecessor hash from invoice history and set evaluated_at for repeatable checks. Omitting the timestamp uses the native clock.

    All bundled UBL schemas are embedded. Installed packages do not need the source checkout, Java, or an external SDK installation. Local validation does not establish gateway acceptance or certificate issuer trust. See the validation reference.

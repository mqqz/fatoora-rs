    CSR and private keys¶

    A certificate signing request (CSR) binds a device identity to a public key. Create properties, generate or load a private key, then build the CSR for the selected environment. For a complete runnable workflow, follow Generate a CSR and private key.

    Property values¶

    Every field is required. The constructor and properties-file parser apply the same validation. Supply your own registered identity values for onboarding; the example properties file contains demonstration data.

    Field / properties-file key Expected value
    common_name / csr.common.name Device or solution common name.
    serial_number / csr.serial.number Solution serial number in the format required for your device.
    organization_identifier / csr.organization.identifier Organization VAT identifier.
    organization_unit_name / csr.organization.unit.name Branch or organizational unit.
    organization_name / csr.organization.name Legal organization name.
    country_name / csr.country.name Exactly two ASCII letters, such as SA.
    invoice_type / csr.invoice.type Exactly four 0 or 1 digits, such as 1100.
    location_address / csr.location.address Business location.
    industry_business_category / csr.industry.business.category Business activity.

    Text fields must contain non-whitespace text and cannot contain ! @ # $ % & * _ <. Country and invoice-type fields have the stricter formats above. Values are not trimmed or normalized by the constructor. Country validation checks the two-letter format, not membership in the ISO country list. Serial numbers and organization identifiers are not checked against registration records. Passing local validation does not guarantee that ZATCA accepts the identity.

    Properties text uses key=value entries. Missing required keys fail; unknown keys are ignored and repeated keys use their last value. File-loading methods read UTF-8.

    Operations and formats¶

    Operation Input Result and behavior
    Create properties The nine fields above, in table order Validated properties, or a validation error.
    Parse properties Properties text or a file path Validated properties; fails on unreadable files, malformed text, or missing fields.
    Generate a key No input A new random secp256k1 private key.
    Load a key PKCS#8 PEM text or DER bytes Private key; malformed or incompatible key material fails.
    Build a CSR Properties, private key, environment New CSR signed by the supplied key; properties and key remain usable.
    Load a CSR DER bytes Parsed CSR; this does not establish gateway approval.
    Read subject CSR Formatted distinguished-name text.
    Read extensions CSR Collection of encoded extension values for inspection.
    Output format Contents Typical use
    Key PEM / DER PKCS#8 private-key material Save or reload the signing key.
    CSR PEM Text with certificate-request delimiters Save a readable csr.pem file.
    CSR DER Binary certificate request Binary storage or parsing.
    CSR Base64 Base64 of DER bytes Consumers that explicitly require encoded DER.
    CSR PEM Base64 Base64 of complete PEM text ZATCA credential requests; the API client performs this conversion.

    Keep the private key: the CSR contains its public key, not the private key needed for invoice signing. Serialization returns data and does not write files.

    All nine arguments are strings.

    Call Returns
    CsrProperties.fromPropertiesStr(text) CsrProperties; text is a string.
    properties.build(key, env) Csr; key is a SigningKey, env is 0, 1, or 2.
    SigningKey.generate() SigningKey
    SigningKey.fromPem(pem) / SigningKey.fromDer(der) SigningKey; pass PEM string / array of byte numbers.

    csr.toBase64() / csr.toPemBase64() String
    csr.subjectString() String
    csr.extensionValuesDer() BytesList

    These operations are synchronous and throw an Error with a BindingError cause on failure. Read files with your application's file APIs, then call fromPropertiesStr; no file-path constructor is exposed. Environment numbers are 0 non-production, 1 simulation, 2 production. Copy returned bytes with Uint8Array.from(bytes.asSlice()) before retaining them across later calls. See JavaScript resource handling.

    Use the Fatoora namespace. Use using for returned objects, including Bytes and BytesList. Errors throw BindingErrorException. Use using var view = bytes.AsSlice(); and copy bytes with view.Clone(). See C# resource handling.

    typedef struct FatooraCsrOptions {
    const char *common_name;
    const char *serial_number;
    const char *organization_identifier;
    const char *organization_unit_name;

    FatooraBytesList **out,
    FatooraError **error);

    Each operation returns FatooraStatus; FATOORA_OK means out contains the result. Other statuses indicate failure; inspect and release the optional FatooraError. DER input is a byte pointer plus byte count; PEM and property inputs are text. Inputs are borrowed for the call, and building does not consume properties or keys.

    Returned handles are owned. Release them with fatoora_csr_properties_free, fatoora_signing_key_free, fatoora_csr_free, fatoora_bytes_free, or fatoora_bytes_list_free as appropriate. Release returned text with fatoora_string_free. See C errors and ownership.

    Validate ZATCA invoice XML¶

    Check an invoice before submission and inspect the results to decide what needs fixing. Choose a schema check for XML structure, or the local ZATCA profile for business rules and applicable integrity checks.

    Check What it tells you
    UBL schema Whether the XML conforms to the bundled invoice schema
    Local ZATCA profile Business-rule findings, applicable signature/QR checks, and which stages were covered

    Neither check establishes ZATCA gateway acceptance or certificate issuer trust. Building, parsing, or signing an invoice does not automatically run the full local profile.

    Prepare the inputs¶

    Save invoice.xml in your working folder. For the local ZATCA check, also save previous-hash.txt. This file supplies the known predecessor context for this demonstration invoice. For real invoices, use the previous invoice's hash from your trusted invoice history; do not copy the current document's claimed predecessor value as independent evidence.

    Validate the original XML. Parsing and reserializing it first can change the document being checked. All schemas are bundled; the check does not contact a gateway.

    The sample is unsigned: it is useful for a successful schema check and for exploring ZATCA findings. Do not expect its full local report to pass signature checks.

    Run the example¶

    Choose your language, then follow its setup and run instructions.

    Install Rust and Cargo, then create a project:

    cargo new fatoority-guide
cd fatoority-guide
cargo add fatoora-core

    Also add the JSON serializer used to print the report:

    cargo add serde_json

    Save the code below as src/main.rs. Put the input files in the project root and run:

    cargo run

    Download this example.

    use fatoora_core::config::{Config, EnvironmentType};
use fatoora_core::invoice::validation::{
    validate_xml_invoice_from_str, validate_zatca_invoice_from_str, ZatcaValidationOptions,
};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let config = Config::new(EnvironmentType::NonProduction);
    let xml = std::fs::read_to_string("invoice.xml")?;
    if std::env::args().any(|arg| arg == "--zatca") {
        let options = ZatcaValidationOptions {
            previous_invoice_hash: Some(std::fs::read_to_string("previous-hash.txt")?.trim().into()),
            ..Default::default()
        };
        let report = validate_zatca_invoice_from_str(&xml, &config, &options)?;
        println!("{}", serde_json::to_string_pretty(&report)?);
        if !report.is_valid() { std::process::exit(1); }
    } else {
        validate_xml_invoice_from_str(&xml, &config)?;
        println!("XSD valid");
    }
    Ok(())
}

    Run the local ZATCA checks

    cargo run -- --zatca

    The example prints the JSON report and exits nonzero when is_valid is false. Inspect stages for the findings rather than treating all failures as execution errors.

    import com.fatoora.*
import java.io.File
import kotlinx.serialization.json.*

fun main(args: Array<String>) {
    Config.create(0).use { config ->
        val xml = File("invoice.xml").readText()
        if (args.contains("--zatca")) {
            val hash = File("previous-hash.txt").readText().trim()
            val options = kotlinx.serialization.json.buildJsonObject {
                put("previous_invoice_hash", kotlinx.serialization.json.JsonPrimitive(hash))
            }.toString()
            val json = Xml.validateZatca(config, xml, options)
            println(json)
            val report = kotlinx.serialization.json.Json.parseToJsonElement(json).jsonObject
            if (!report.getValue("is_valid").jsonPrimitive.boolean) kotlin.system.exitProcess(1)
        } else {
            Xml.validate(config, xml)
            println("XSD valid")
        }
    }
}

    Download this example. Try-with-resources releases native objects. The library itself supports Java 8+; see Java setup for platform prerequisites, Gradle installation, and Android configuration.

    import com.fatoora.*;
import java.nio.file.*;
import java.nio.charset.StandardCharsets;

public class Guide {
    static String read(String path) throws java.io.IOException {
        return new String(Files.readAllBytes(Paths.get(path)), StandardCharsets.UTF_8);
    }
    static void write(String path, String text) throws java.io.IOException {
        Files.write(Paths.get(path), text.getBytes(StandardCharsets.UTF_8));
    }
    public static void main(String[] args) throws Exception {
        try (Config config = Config.create(0)) {
            String xml = read("invoice.xml");
            if (java.util.Arrays.asList(args).contains("--zatca")) {
                com.google.gson.JsonObject options = new com.google.gson.JsonObject();
                options.addProperty("previous_invoice_hash", read("previous-hash.txt").trim());
                String json = Xml.validateZatca(config, xml, options.toString());
                System.out.println(json);
                boolean valid = com.google.gson.JsonParser.parseString(json).getAsJsonObject()
                    .get("is_valid").getAsBoolean();
                if (!valid) System.exit(1);
            } else {
                Xml.validate(config, xml);
                System.out.println("XSD valid");
            }
        }
    }
}

    Download this example. For other platforms, follow the C installation and linking reference. The cleanup section releases handles and returned strings, including on failure.

    #include "fatoora.h"
#include <stdio.h>
#include <stdlib.h>

static char *read_xml(const char *path) {
    FILE *file = fopen(path, "rb");
    if (!file) return NULL;
    char *xml = NULL;
    if (fseek(file, 0, SEEK_END)) goto done;
    long size = ftell(file);
    if (size < 0 || size > 1024 * 1024) goto done;
    rewind(file);
    xml = malloc((size_t)size + 1);
    if (!xml) goto done;
    if (fread(xml, 1, (size_t)size, file) != (size_t)size) {
        free(xml);
        xml = NULL;
    } else {
        xml[size] = '\0';
    }
done:
    fclose(file);
    return xml;
}

int main(int argc, char **argv) {
    if (argc != 2 && argc != 3) {
        fprintf(stderr, "Usage: %s invoice.xml [validation-options.json]\n", argv[0]);
        return 1;
    }
    FatooraConfig *config = NULL;
    FatooraError *error = NULL;
    char *xml = read_xml(argv[1]);
    if (!xml) {
        fputs("Unable to read invoice XML.\n", stderr);
        return 1;
    }
    bool valid = false;
    char *options = NULL, *report = NULL;
    FatooraStatus status = FATOORA_OK;
#define TRY(call) do { status = (call); if (status != FATOORA_OK) goto cleanup; } while (0)
    TRY(fatoora_config_new(FATOORA_NON_PRODUCTION, &config, &error));
    /* Validate original XML; parsing/reserializing would change the input. */
    if (argc == 3) {
        options = read_xml(argv[2]);
        if (!options) { fputs("Unable to read validation options.\n", stderr); goto cleanup; }
        TRY(fatoora_xml_validate_zatca(config, xml, options, &report, &error));
        puts(report);
        /* Parse is_valid/is_complete with your application's JSON parser before accepting.
           Here exit 0 means the report was produced, not that the invoice passed. */
        valid = true;
    } else {
        TRY(fatoora_xml_validate(config, xml, &valid, &error));
        printf("XSD valid: %s\n", valid ? "true" : "false");
    }
cleanup:
    if (status != FATOORA_OK)
        fprintf(stderr, "Error %d: %s\n", (int)status, fatoora_error_message(error));
    free(options);
    fatoora_string_free(report);
    free(xml);
    fatoora_config_free(config);
    fatoora_error_free(error);
    return status == FATOORA_OK && valid ? 0 : 1;
}

    Save validation-options.json beside the input. It contains predecessor context for the sample only.

    ./validation invoice.xml validation-options.json

    The example prints the JSON report. Exit 0 here means a report was produced; parse is_valid and is_complete with your application's JSON parser before accepting the invoice.

    Install the command-line tool with cargo install fatoora-cli, or extract a release binary and add it to your PATH. See the CLI guide for platform setup. Run beside your input files:

    fatoora validate --invoice invoice.xml

    For local ZATCA rules, use your shell to pass the predecessor hash. In a POSIX shell:

    fatoora validate --invoice invoice.xml --profile zatca --format json \
  --previous-invoice-hash "$(cat previous-hash.txt)"

    In PowerShell:

    fatoora validate --invoice invoice.xml --profile zatca --format json `
  --previous-invoice-hash (Get-Content -Raw previous-hash.txt).Trim()

    The schema command prints OK. The ZATCA command prints a report and returns 0 for valid, 2 for rejected, 3 for execution failure, or 4 for incomplete coverage.

    Interpret the result¶

    A successful schema check prints a success message. It says nothing about business rules or gateway acceptance. A local ZATCA check prints a structured report:

    Result How to use it
    is_valid: true The invoice passes the configured local profile with complete coverage. Keep any warnings.
    is_valid: false, is_complete: true Inspect stage findings and correct the rejected invoice data.
    is_complete: false Required context or a validation stage is missing. Resolve the gap before treating the invoice as checked.
    Execution error The check could not finish normally. Inspect the error and any attached partial report.

    Findings include a stage, code, and message. Warnings alone do not make an otherwise valid report fail. Do not discard them or reduce every failure to a generic “invalid invoice.”

    Understand the coverage¶

    The local profile implements the pinned SDK 238-R3.4.8 adaptations of CEN and Saudi rules: 105 CEN assertion sites and 152 Saudi sites. It runs without an external SDK runtime and uses the same profile in every API environment.

    Under this profile, standard invoices skip signature and QR checks. Simplified invoices check the embedded certificate's key, reference digests, signature, and QR fields. These establish local integrity, not certificate issuer trust.

    The default evaluation time is a single current UTC snapshot. For a reproducible historical test, supply an explicit evaluation time as documented in the validation options. A fixed demonstration clock should not become the default for your live integration.

    If something goes wrong¶

    Symptom What to check
    Schema rejection Read the XML/schema error and correct the indicated structure or value.
    Incomplete predecessor check Supply the trusted previous-invoice hash from your invoice history.
    Signature/QR findings on the sample The downloaded invoice.xml is unsigned. To examine signed input, replace it with your signed XML and its matching predecessor context.
    Different results after editing XML Run checks on the exact document you plan to submit; edits can invalidate signature material.

    Next, submit the invoice and check gateway acceptance. The validation reference covers report fields and error contracts; SDK compatibility records differences from the SDK.

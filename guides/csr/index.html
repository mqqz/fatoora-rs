    Generate a ZATCA CSR and private key¶

    A certificate signing request (CSR) contains the identity and public key of your invoicing device. Use it during onboarding to request credentials from ZATCA. This walkthrough creates a CSR and its matching private key locally.

    Prepare the inputs¶

    Download csr.properties into a working folder. The sample contains demonstration values and targets the non-production environment. You can run it unchanged to learn the workflow.

    For your own device, replace the sample values:

    Property What to supply
    csr.common.name Your device or solution common name
    csr.serial.number The solution serial number in ZATCA's required format
    csr.organization.identifier Your organization's VAT identifier
    csr.organization.unit.name The branch or organizational unit
    csr.organization.name The legal organization name
    csr.country.name The country code, such as SA
    csr.invoice.type The invoice-type capability code required for your device
    csr.location.address The business location
    csr.industry.business.category The business activity

    Use the current field requirements from the ZATCA developer portal when onboarding a real device. The sample values are not a registration for your business. Keep the CSR environment consistent with the API environment you will use next. The examples replace csr.pem and key.pem if those files already exist.

    Run the example¶

    Choose your language, then follow its setup and run instructions.

    Install Rust and Cargo, then create a project:

    cargo new fatoority-guide
cd fatoority-guide
cargo add fatoora-core

    Save the code below as src/main.rs. Put the input files in the project root and run:

    cargo run

    Download this example.

    use fatoora_core::config::EnvironmentType;
use fatoora_core::csr::{CsrProperties, SigningKey};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let text = std::fs::read_to_string("csr.properties")?;
    let properties = CsrProperties::from_properties_str(&text)?;
    let key = SigningKey::generate();
    let csr = properties.build(&key, EnvironmentType::NonProduction)?;
    std::fs::write("csr.pem", csr.to_pem()?)?;
    std::fs::write("key.pem", key.to_pem()?)?;
    println!("Saved csr.pem and key.pem");
    Ok(())
}

    Download this example. Try-with-resources releases native objects. The library itself supports Java 8+; see Java setup for platform prerequisites, Gradle installation, and Android configuration.

    import com.fatoora.*;
import java.nio.file.*;
import java.nio.charset.StandardCharsets;

public class Guide {
    static String read(String path) throws java.io.IOException {
        return new String(Files.readAllBytes(Paths.get(path)), StandardCharsets.UTF_8);
    }
    static void write(String path, String text) throws java.io.IOException {
        Files.write(Paths.get(path), text.getBytes(StandardCharsets.UTF_8));
    }
    public static void main(String[] args) throws Exception {
        try (CsrProperties properties = CsrProperties.fromPropertiesStr(read("csr.properties"));
             SigningKey key = SigningKey.generate();
             Csr csr = properties.build(key, 0)) {
            write("csr.pem", csr.toPem());
            write("key.pem", key.toPem());
        }
        System.out.println("Saved csr.pem and key.pem");
    }
}

    Download this example. For other platforms, follow the C installation and linking reference. The cleanup section releases handles and returned strings, including on failure.

    The example saves key.pem and csr.pem. Keep the key private.

    #include "fatoora.h"
#include <stdio.h>

static int write_pem(const char *path, const char *pem) {
    FILE *file = fopen(path, "wb");
    if (!file) return 0;
    int written = fputs(pem, file) >= 0;
    return fclose(file) == 0 && written;
}

int main(int argc, char **argv) {
    if (argc != 2) {
        fprintf(stderr, "Usage: %s csr.properties\n", argv[0]);
        return 1;
    }
    FatooraCsrProperties *properties = NULL;
    FatooraSigningKey *key = NULL;
    FatooraCsr *csr = NULL;
    FatooraError *error = NULL;
    char *csr_pem = NULL, *key_pem = NULL;
    FatooraStatus status = FATOORA_OK;
    int exit_code = 1;
#define TRY(call) do { status = (call); if (status != FATOORA_OK) goto cleanup; } while (0)
    TRY(fatoora_csr_properties_parse_csr_config_file(argv[1], &properties, &error));
    TRY(fatoora_signing_key_generate(&key, &error));
    TRY(fatoora_csr_properties_build(properties, key, FATOORA_NON_PRODUCTION, &csr, &error));
    TRY(fatoora_csr_to_pem(csr, &csr_pem, &error));
    TRY(fatoora_signing_key_to_pem(key, &key_pem, &error));
    if (!write_pem("key.pem", key_pem) || !write_pem("csr.pem", csr_pem)) {
        fputs("Unable to write key.pem or csr.pem.\n", stderr);
        goto cleanup;
    }
    puts("Saved csr.pem and key.pem");
    exit_code = 0;
cleanup:
    if (status != FATOORA_OK) fprintf(stderr, "Error %d: %s\n", (int)status, fatoora_error_message(error));
    fatoora_string_free(key_pem);
    fatoora_string_free(csr_pem);
    fatoora_csr_free(csr);
    fatoora_signing_key_free(key);
    fatoora_csr_properties_free(properties);
    fatoora_error_free(error);
    return exit_code;
}

    Install the command-line tool with cargo install fatoora-cli, or extract a release binary and add it to your PATH. See the CLI guide for platform setup. Run beside your input files:

    fatoora csr --csr-config csr.properties --generated-csr csr.pem --private-key key.pem --pem

    Check the result¶

    You should have a CSR beginning with -----BEGIN CERTIFICATE REQUEST----- and a key beginning with -----BEGIN PRIVATE KEY-----. The selected example explains where it writes those blocks. The CSR can be submitted for onboarding; keep the private key for signing and do not send it as part of the CSR request.

    The examples use PEM text. Some integrations expect base64 DER instead; choose the representation required by the receiving endpoint rather than encoding PEM again.

    If something goes wrong¶

    Symptom What to check
    Configuration file not found Run from the folder containing csr.properties, or change the path in your example.
    Properties cannot be parsed Check spelling, missing values, and the property names in the table above.
    Onboarding rejects the request Check business identifiers, the required device fields, OTP, and environment against the portal response.

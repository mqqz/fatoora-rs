    Connect to ZATCA APIs¶

    Use the API client to submit invoices and inspect the gateway's response. This walkthrough reports a simplified invoice to the non-production environment and checks whether reporting was accepted. It requires network access and credentials.

    Choose the operation¶

    Your task Operation Credentials
    Test an invoice during onboarding Compliance check Compliance credentials
    Submit a simplified invoice Reporting Production-type credentials for the selected environment
    Submit a standard invoice Clearance Production-type credentials for the selected environment

    A credential's type and its environment are separate. Production-type credentials can target non-production, simulation, or production; the client and credentials must agree. Every example below uses non-production. Changing only the client environment does not convert credentials issued for another environment.

    Obtain credentials¶

    1. Generate a CSR and private key for the target environment.
    2. Obtain the onboarding one-time password (OTP) through the appropriate ZATCA flow, then submit the CSR to request compliance credentials.
    3. Use those credentials to complete the required invoice compliance checks.
    4. Request production-type credentials for that environment, then retain the returned token and secret for reporting or clearance.

    See the credential endpoint reference and ZATCA developer portal for the request fields and environment-specific onboarding requirements. A successful compliance check alone is not reporting or clearance acceptance.

    Prepare the inputs¶

    Use your own signed.xml: a simplified invoice signed with the certificate and key associated with your credentials. The offline guide's public test certificate is not a substitute for credentials issued to you.

    Set ZATCA_TOKEN and ZATCA_SECRET in the environment of the process running the example. Do not paste credentials into source files. The example reads these names and fails before sending a request if either value is missing.

    Run the example¶

    Choose your language, then follow its setup and run instructions.

    Install Rust and Cargo, then create a project:

    cargo new fatoority-guide
cd fatoority-guide
cargo add fatoora-core

    Add the async runtime:

    cargo add tokio --features macros,rt-multi-thread

    Save the code below as src/main.rs. Put the input files in the project root and run:

    Download this example.

    Set ZATCA_TOKEN and ZATCA_SECRET in your process environment before running. The example makes a real request to the non-production gateway.

    use fatoora_core::api::{CsidCredentials, Production, ZatcaClient};
use fatoora_core::config::{Config, EnvironmentType};
use fatoora_core::invoice::xml::parse::parse_signed_invoice_xml;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let environment = EnvironmentType::NonProduction;
    let token = std::env::var("ZATCA_TOKEN")?;
    let secret = std::env::var("ZATCA_SECRET")?;
    let client = ZatcaClient::new(Config::new(environment))?;
    let credentials = CsidCredentials::<Production>::new(environment, None, token, secret);
    let xml = std::fs::read_to_string("signed.xml")?;
    let invoice = parse_signed_invoice_xml(&xml)?;
    let response = client.report_simplified_invoice(&invoice, &credentials, false, Some("en")).await?;
    response.ensure_accepted()?;
    println!("Invoice reporting accepted");
    Ok(())
}

    from pathlib import Path
import os
from fatoora.api import CsidProduction, ZatcaClient
from fatoora.config import Config, Environment
from fatoora.invoice import parse_signed_invoice_xml

# Use credentials issued for this same environment.
environment = Environment.NON_PRODUCTION
token = os.environ["ZATCA_TOKEN"]
secret = os.environ["ZATCA_SECRET"]
with Config(environment) as config, ZatcaClient(config) as client:
    with CsidProduction.new(environment, token, secret, None) as credentials:
        with parse_signed_invoice_xml(Path("signed.xml").read_text(encoding="utf-8")) as invoice:
            with client.report_simplified_invoice(invoice, credentials, False, "en") as response:
                response.ensure_accepted()
                print("Invoice reporting accepted")

    import com.fatoora.*;
import java.nio.file.*;
import java.nio.charset.StandardCharsets;

public class Guide {
    static String read(String path) throws java.io.IOException {
        return new String(Files.readAllBytes(Paths.get(path)), StandardCharsets.UTF_8);
    }
    static void write(String path, String text) throws java.io.IOException {
        Files.write(Paths.get(path), text.getBytes(StandardCharsets.UTF_8));
    }
    public static void main(String[] args) throws Exception {
        int environment = 0; // Non-production; credentials must match.
        String token = java.util.Objects.requireNonNull(System.getenv("ZATCA_TOKEN"), "Set ZATCA_TOKEN first");
        String secret = java.util.Objects.requireNonNull(System.getenv("ZATCA_SECRET"), "Set ZATCA_SECRET first");
        try (Config config = Config.create(environment);
             ZatcaClient client = ZatcaClient.create(config);
             CsidProduction credentials = CsidProduction.create(environment, null, token, secret);
             SignedInvoice invoice = SignedInvoice.fromXml(read("signed.xml"));
             ValidationResponse response = client.reportSimplifiedInvoice(invoice, credentials, false, "en")) {
            response.ensureAccepted();
            System.out.println("Invoice reporting accepted");
        }
    }
}

    Download this example. For other platforms, follow the C installation and linking reference. The cleanup section releases handles and returned strings, including on failure.

    Set ZATCA_TOKEN and ZATCA_SECRET in your process environment before running. The example makes a real request to the non-production gateway.

    This example uses a blocking request; run it away from your application's UI thread.

    #include "fatoora.h"
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char **argv) {
    if (argc != 2) {
        fprintf(argc == 1 ? stdout : stderr,
            "Usage: %s signed-invoice.xml\n"
            "Submits a simplified invoice to the non-production gateway.\n", argv[0]);
        return argc == 1 ? 0 : 1;
    }
    const char *token = getenv("ZATCA_TOKEN"), *secret = getenv("ZATCA_SECRET");
    if (!token || !secret) { fputs("Set ZATCA_TOKEN and ZATCA_SECRET first.\n", stderr); return 1; }
    FatooraConfig *config = NULL;
    FatooraSignedInvoice *invoice = NULL;
    FatooraCsidProduction *credentials = NULL;
    FatooraZatcaClient *client = NULL;
    FatooraValidationResponse *response = NULL;
    FatooraError *error = NULL;
    FatooraStatus status = FATOORA_OK;
    int exit_code = 1;
#define TRY(call) do { status = (call); if (status != FATOORA_OK) goto cleanup; } while (0)
    TRY(fatoora_signed_invoice_from_file(argv[1], &invoice, &error));
    TRY(fatoora_config_new(FATOORA_NON_PRODUCTION, &config, &error));
    TRY(fatoora_zatca_client_create(config, &client, &error));
    TRY(fatoora_csid_production_create(FATOORA_NON_PRODUCTION, NULL,
        token, secret, &credentials, &error));
    TRY(fatoora_zatca_client_report_simplified_invoice(client, invoice,
        credentials, false, "en", &response, &error));
    /* Receiving a response does not establish acceptance. */
    TRY(fatoora_validation_response_ensure_accepted(response, &error));
    puts("Invoice reporting accepted.");
    exit_code = 0;
cleanup:
    if (exit_code) fprintf(stderr, "Error %d: %s\n%s\n", (int)status,
        fatoora_error_message(error), fatoora_error_details_json(error));
    fatoora_validation_response_free(response);
    fatoora_zatca_client_free(client);
    fatoora_csid_production_free(credentials);
    fatoora_signed_invoice_free(invoice);
    fatoora_config_free(config);
    fatoora_error_free(error);
    return exit_code;
}

    Check the result¶

    The example prints Invoice reporting accepted only after checking the reporting outcome. An HTTP 2xx response that decodes successfully does not by itself mean the invoice was accepted.

    Outcome What to do
    Accepted Record the response and retain warnings. For compliance, this means only that the compliance check passed.
    Rejected Inspect validation messages and correct the invoice before another submission.
    Unknown Inspect the original status fields; missing, unfamiliar, or contradictory evidence cannot establish acceptance.

    Non-2xx responses are errors and retain HTTP status and response details when available. Avoid blind retries when the result of a submission is uncertain.

    Use clearance for a standard invoice¶

    Choose the clearance operation with a standard invoice and credentials for the same environment. Check the clearance outcome, then retrieve the returned cleared invoice if your workflow needs the gateway document. Save that XML directly.

    Acceptance does not guarantee the optional cleared document is present or decodable. Decoding the field establishes UTF-8 text only; it does not parse XML or verify a signature. The clearance reference describes the operation and response accessors.

    If something goes wrong¶

    Symptom What to check
    Missing credential variable Set both named environment variables in the process that runs the example.
    Authentication or authorization error Check the token, secret, credential type, and environment together.
    Invoice rejected Read the gateway's validation messages and compare them with local validation.
    Network error or timeout Check connectivity and the selected endpoint; determine whether a request reached the gateway before retrying.
    Accepted clearance without usable XML Handle the missing or invalid document explicitly; do not silently substitute the submitted XML.

    See the API reference for onboarding, renewal, compliance, reporting, clearance, and complete response contracts.
